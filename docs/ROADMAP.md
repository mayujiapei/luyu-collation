# 国奖路线图（ROADMAP）— 古籍智能校勘系统

> 版本：v1.0（2026-10-03）。本文档是战略统领：PRD/TECH_DESIGN/API 三份文档描述**阶段一**的范围与契约；阶段二、三的增量在启动对应阶段时先回写进那三份文档再施工。
> 目标：**全国总决赛获奖**（省赛一、二等奖晋级国赛，总决赛 11 月中下旬）。

## 1. 战略判断

- 省赛决胜因素 = 产品完成度（功能全、演示顺、有数据）。
- 国赛决胜因素 = **学科方法论创新 + 证据硬度**。评审组含 AI 与对应学科（文献学）双背景评委，"调 API 套壳"在答辩环节无法存活。
- 因此全部投入必须能兑换到评分表最高档：
  - 创新性（14-20 分档）：学科问题解决**新方法** → 校勘四法计算化（§2）；
  - 方案可行性（14-20 分档）：技术架构非套壳 → diff + RAG + 多路融合 + 领域模型；
  - 应用效果（14-20 分档）：证据硬度 → 基准、论文、盖章合作、完整案例（§4）；
  - 推广价值：基准 + 平台可被同类院校/研究所复用。

## 2. 核心创新：校勘四法引擎（陈垣方法论计算化）

| 引擎 | 学科原型 | 技术实现 | 输出 |
|---|---|---|---|
| 对校 | 版本对勘 | 多版本文本 diff 算法（确定性） | 异文清单 |
| 本校 | 上下文互证 | 全书用字一致性统计 + 规则 | 用字疑点 |
| 他校 | 他书引文比对 | 公共古籍语料向量检索（RAG） | 他书写法证据 |
| 理校 | 义理推断 | 大模型（语义/音韵/上下文） | 推断建议 |

- **证据链融合**：四路结果按类型对齐 → 置信度融合（规则命中数 + 检索证据强度 + 模型自评，加权校准）→ 每条建议携带可展开的证据链（版本出处、他书出处、义理依据）。
- **出注规范**：校勘记按文献学体例逐条注明证据来源，与"通用错别字工具"形成本质区隔，同时回应大模型幻觉质疑。

## 3. 技术栈修订（相对 TECH_DESIGN v1.0 的变更项）

| 项 | 阶段一定稿 | 国奖路线修订 | 原因 |
|---|---|---|---|
| 后端 | Node + Express | **Python + FastAPI** | RAG/语料处理/微调/评测全在 Python 生态；避免中期迁移 |
| 检索 | 无 | bge-m3 embedding + Milvus Lite / Qdrant 本地 | 他校引擎的语料检索 |
| 模型 | 仅 API（Qwen/DeepSeek） | API + **Qwen2.5-7B LoRA 领域微调**，vLLM/Ollama 本地推理 | 对比实验硬证据 + 离线演示 + 自主可控叙事 |
| 持久化 | 无状态 | SQLite（版本库/语料库/评测结果） | 多版本对勘与基准需要 |
| 前端 | 不重构 | 不重构 + 新增三视图：版本对勘、证据链面板、评测看板 | UI 已是卖点；新视图服务新引擎 |
| 校勘记/繁简 | 模板 + opencc-js | 不变 | 规则任务不交模型，原则延续 |

## 4. 国奖证据清单（按硬度排序）

1. **评测基准**：数百段公共版权古籍语料 + 标注规范 + 多模型（≥4 个，含领域微调模型）对比 leaderboard + 人工复核子集 → 既是应用效果数据，又是论文素材。
2. **论文**：基准与四法引擎方法投稿中文计算语言学 / 数字人文方向会议或期刊；录用通知（甚至在投证明）进佐证材料。
3. **软件著作权**：尽早提交申请，受理通知书即可入佐证。
4. **合作证明**：图书馆古籍部 / 文学院 / 古籍出版社试点，**盖章**试用或合作意向证明。
5. **完整案例**：用系统校勘一部真实文献（短篇文集或一卷方志），产出全文校勘记，作为方案与答辩的 case study。
6. **用户研究**：跨校、多角色（本科生/研究生/教师/编辑）正式调研，前后两测。

## 5. 三阶段武装

### 阶段一：入场券（校赛 / 省赛报名）
- 范围 = PRD v1.0（F1–F8）+ TECH_DESIGN v1.0，唯后端直接以 FastAPI 起步（不再经过 Express）。
- 出口标准：真实 AI 链路端到端可用；基础实验数据 + 试点问卷；材料按规范提交。

### 阶段二：装武器（省赛 → 国赛前）
- 四法引擎全部落地；RAG 语料库构建（公共版权：ctext、Kanripo 等）；
- 前端版本对勘视图 + 证据链面板；
- 软著申请提交；试点合作洽谈并拿到至少一份盖章证明；
- 评测基准数据集构建启动（语料收集 + 标注规范 v1）。

### 阶段三：国赛冲刺（总决赛前）
- LoRA 领域微调 + 与通用模型对比实验（准确率/F1 提升需显著）；
- 评测看板页；论文投出；完整案例校勘记定稿；
- 国赛版演示视频（主线：痛点 → 四法引擎证据链 → 完整案例 → 基准数据）；
- 答辩演练：预设"与通用工具有何区别""置信度如何可信""数据版权合规"三类问题。

## 6. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 微调效果不显著 | 对比实验对象保留提示工程 + RAG 路线，任一显著即成证据；微调非唯一支柱 |
| 公共语料版权 | 仅用公共版权/开放授权文本，来源清单进附录并注明出处 |
| 合作证明拿不到 | 降级为导师/任课教师签字的教学试用证明（注意匿名化处理：材料中不出现校名） |
| 四法引擎工程量超预期 | 保底形态：对校 + 理校双引擎先行（diff + LLM 成本最低），他校/本校作为"已实现部分场景"，叙事不断裂 |

## 7. 不变量（任何阶段不得突破）

- 参赛材料匿名红线（无校名/Logo/导师/真名）。
- 主链路无硬编码演示数据；模型输出必须 schema 校验。
- 代码与文档冲突以文档为准；范围变化先改文档。
